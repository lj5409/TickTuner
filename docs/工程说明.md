## 1. 项目定位与核心原则

**TickTuner** 是一款完全离线、无网络权限、面向吉他手的 Android 工具箱，整合 **调音器 / 节拍器 / 和弦查找** 三大模块，通过侧载签名 APK 分发使用。

### 核心工程红线
1. **完全离线零联网**：禁止申请 `INTERNET` 权限，不引入网络/埋点/广告依赖。
2. **最小依赖**：仅使用 Jetpack Compose / Material 3 / Lifecycle / Navigation / WindowManager / DataStore / kotlinx-coroutines / kotlinx-serialization，**不随意引入第三方 UI 或手势库**。
3. **不丢状态、不断音频**：`MainActivity` 声明 `configChanges="orientation|screenSize|smallestScreenSize|screenLayout|keyboardHidden|uiMode"`，`GToolApp` 中 `NavHost` 始终保持在单一结构槽位，旋转屏幕、切换内外屏或折展折叠屏时不得销毁 ViewModel 或中断播放/拾音。
4. **深色优先与大触控目标**：全局深色主题（`Bg = #0B0F0E`，主强调色 `Accent = #2EE6A8`），状态栏/导航栏固定深色对比度；常用操作触控目标 ≥ 48 dp，适合手持吉他单手操作。
5. **音频主时钟与线程隔离**：音频采集/合成/调度在后台线程完成，通过 `StateFlow` / `Channel` / `SharedFlow` 通知 Compose；UI 禁止使用 `delay()` 自计时驱动节拍器动画。
6. **逻辑与 UI 解耦**：纯乐理与 DSP 算法放在 `core/music` 与 `core/audio`（无 Android 依赖或弱依赖），新增核心逻辑必须配套 JVM 单元测试（JUnit 4）。

## 4. 四态多形态自适应规范（直板机 & vivo X Fold3 Pro）

应用通过 [WindowPosture.kt](file:///C:/Users/Jon/orca/workspaces/GTool%20App/节拍器界面调整/app/src/main/java/com/gtool/ui/WindowPosture.kt) 监听 `WindowInfoTracker.windowLayoutInfo(activity)` 与窗口尺寸，统一判定 4 种姿态（不做机型硬编码）：

| 姿态枚举 | 判定条件 | 导航栏策略（`GToolApp`） | 设计理念 |
|---|---|---|---|
| `PORTRAIT` | 其余竖屏情况（直板机、折叠屏外屏竖屏） | 底部 `NavigationBar` | 单手操作优先，核心舞台置顶 |
| `LANDSCAPE_COMPACT` | 非悬停，`width > height && height < 550.dp`（直板横屏、折叠屏外屏横屏/帐篷模式） | **调音器 & 节拍器隐藏导航栏**（保留 `safeDrawing` 避让挖孔/手势条）；和弦保留底部栏 | 横屏即进入**纯演奏/纯调音动作**，隐藏一切无关设置，满屏展示无需滑动 |
| `TABLETOP` | `FoldingFeature.state == HALF_OPENED` 且 `orientation == HORIZONTAL` | **调音器 & 节拍器隐藏导航栏**（避免横跨折痕） | 按物理 `hingeBounds` 精确分隔：**上半屏**（立起面向演奏者）只放纯净大视觉舞台；**下半屏**（平放桌面）提供大折叠左右双栏完整控制台与全部设置（窄屏单栏滚动） |
| `UNFOLDED_EXPANDED` | 非悬停或竖向半折，`width >= 600.dp && height >= 550.dp`（X Fold3 Pro 8.03" 内屏 2200×2480 任意方向） | 全 App 切换为左侧细长 `NavigationRail` | 左右双栏布局，主视觉在左、次级控制/设置在右，并检测 `isVerticalBookFold` 精确避让竖向折痕 |

### 页面记忆约定
- `GToolApp` 使用独立 `SharedPreferences("gtool_nav")` 同步读写 `last_tab_route`（默认 `"tuner"`），确保冷启动（含被后台查杀后重启）直接进入上次使用的模块，零闪烁且不误触发调音器麦克风权限。

## 5. 各模块功能设计与交互要求

### 5.1 调音器（`feature/tuner`）
- **拾音与防误判**：48 kHz 滑动窗 + YIN（2048/4096 自适应）+ 5 帧中值滤波 + EMA 平滑；换弦/八度跳变（>400 音分）立即重置平滑。**严禁跨八度折叠音分**，差八度显示真实音分并提示「高过八度 / 低过八度」。
- **视觉与交互要求**：
  - `±3` 音分内变绿显示「准」；
  - 目标提示行严格**单行不换行**（固定最小高度，避免有声/无声切换引起下方跳动）；
  - 弦位列表紧凑显示（**不在每根弦下方重复显示“点击锁定”**）；
  - 参考音改为**持续循环播放**（`ToneGenerator.playLoop`，叠加 2/3 次谐波），播放时高亮显示红色「■ 停止」按钮；
  - 每根弦保留各自最后一次识别到的音分差值（`lastStringCents`），切换页面（`ON_PAUSE`）、切换调弦或重启 App 后自动清空。
- **调弦管理与拖动排序**：
  - 9 套内置调弦（只读，可另存为自定义）+ 自定义调弦（新建、改名、逐弦改音名与八度、删除）。
  - `TuningManagerDialog` 为内置与自定义**统一 `LazyColumn` 列表**，左侧 6 点手柄按住即可上下实时拖动排序（含触感反馈、悬起高亮、边缘自动滚动、首项锚点防跳动）。
  - 排序结果写入 `AppSettings.tuningOrder` 持久化，全局同步生效于调音器「选择调弦」、大屏/悬停「快速切换调弦」以及和弦页调弦栏。
- **四态布局**：
  - **竖屏**：顶部调弦栏（切换 + A4 / ♯♭ / 调弦管理）+ 半圆表盘卡 + 紧凑 6 弦列表。
  - **横屏 / 帐篷**：隐藏导航栏与设置；左侧自适应大调音表（`-50..+50` 刻度自动对齐弧宽）+ 右侧两列满屏弦位网格（左列 6/5/4、右列 3/2/1），**满屏无滑动**。
  - **半折叠（Tabletop）**：上半屏纯净大调音表；下半屏大折叠下左右双栏（左两列弦位 + 右调音参数与快速切换调弦列表）。
  - **完全展开（Unfolded）**：左侧 `NavigationRail` + 左栏（大调音表 + 快捷参数卡）+ 右栏（弦位列表 + 快速切换调弦卡），避让竖向折痕。

### 5.2 节拍器（`feature/metronome`）
- **时钟与音频**：`ClickPlayer` 按写入采样点数调度 `BeatEvent(nanoTime)`；静音模式下混音严格判断 `soundEnabled` 并在切换静音时清空尾音缓冲。
- **视觉舞台（`BeatVisualizer`）**：
  - 竖屏 / 悬停 / 展开采用 **方案 B（左对齐拉长药丸横条竖向堆叠）**；横屏 / 帐篷采用 **底部对齐竖直药丸左到右排列**。
  - 长度 + 颜色 + 亮度 + 光晕区分轻重拍（重拍 100% 琥珀金 `Warm`、普通拍 68% 翡翠绿 `Accent`、静音拍 38% 虚线空心微闪）；**不在拍条右侧显示“重/中/静”文字**。
  - 取消独立开始/暂停按钮，点击整块拍条舞台即启停（仅首次进入显示一次性引导提示，点击后持久化隐藏）。
  - 所有每帧脉冲强度仅在 Canvas 绘制阶段读取，零每帧 Compose 重组。
- **BPM 控制与内置数字键盘（`BpmControls`）**：
  - 点击 BPM 数字弹出应用内自绘数字键盘（支持 `30–300` 校验、首键覆盖、清空、退格，**严禁唤起系统输入法**）；横屏自动切为紧凑双栏小键盘避免遮挡或需要滑动。
  - 竖屏/悬停/展开底栏为 `[ − ]  [ 拍号▾ ]  [ + ]`（`−`/`+` 支持长按连续步进，点拍号直切 `2/4 · 3/4 · 4/4 · 6/8`）；横屏右侧为竖向 BPM 滑杆（下 30 → 上 300）+ 竖排 `BPM / + / − / Tap`。
- **静音输出与光敏安全**：
  - 声音 / 屏幕 / 闪光灯 / 振动可任意组合；**屏幕全屏闪烁仅跟随主节拍（`subIndex == 0`），不随细分改变**，静音拍不误闪全屏；
  - 闪烁频率 > 3 Hz 自动降级为柔和脉冲并提示，开启强闪需二次确认；闪光灯不支持强度调节时自动降级为开/关。
- **四态布局**：
  - **竖屏**：首屏 100% 视口高度（拍条舞台 + BPM 控制 + Tap），上滑直接露出全部展开的三组设置卡（取消二次折叠）。
  - **横屏 / 帐篷**：隐藏导航与设置，左侧竖直拍条 + 右侧竖向 BPM 滑杆与按钮。
  - **半折叠（Tabletop）**：上半屏纯净拍条；下半屏大折叠左右双栏（左 BPM 控制 + 右全部设置卡片）。
  - **完全展开（Unfolded）**：左侧 `NavigationRail` + 左栏（拍条 + BPM）+ 右栏（独立滚动全部设置卡片）。

### 5.3 和弦查找（`feature/chords`）
- 12 根音 × 18 种和弦类型；组成音卡片显示音名、音级与跟随全局 `A4` 的频率。
- 6 弦 15 品 Canvas 指板：根音红（`RootRed`）、和弦音蓝（`ChordBlue`）、非和弦音淡灰；播放时逐弦拨动涟漪动画。
- 指法生成（`VoicingGenerator`）：支持任意调弦（联动调音器自定义调弦及排序）与 Capo 0–7 品；缓存 key 包含各弦 MIDI 音高，修改/删除自定义调弦时立即 `clearCache()` 重算；支持标准大横按与唯一手指编号分配；播放中切换 Capo 或调弦自动用新指法续播。
- 播放引擎：Karplus-Strong 物理建模（`GuitarSynth`），支持下扫/上扫/自定义分解顺序（1–6 弦号、最多 16 步、默认 `53231323`、350 ms 防抖持久化、循环播放中修改即时生效）。

## 6. 数据持久化与共享状态契约

数据仓库由 `GtoolApplication.repository`（[AppRepository.kt](file:///C:/Users/Jon/orca/workspaces/GTool%20App/节拍器界面调整/app/src/main/java/com/gtool/core/data/AppRepository.kt)）统一管理，底层为 `DataStore<Preferences>("gtool")`：

- `Keys.SETTINGS` → `AppSettings` JSON：
  - `a4: Double`（默认 `440.0`）
  - `useFlats: Boolean`（默认 `false`）
  - `capo: Int`（默认 `0`）
  - `lastTuningId: String`（默认 `"standard"`）
  - `showNoteNamesOnFretboard: Boolean`（默认 `true`）
  - `arpeggioPattern: String`（默认 `"53231323"`）
  - `tuningOrder: List<String>`（默认 `emptyList()`，存全量调弦排序 ID）
  - `metronome: MetronomeSettings`
- `Keys.CUSTOM_TUNINGS` → `List<TuningDto>` JSON（仅自定义调弦）。
- `AppState.allTunings` 通过 `TuningLibrary.orderedAll(customTunings, settings.tuningOrder)` 统一输出，确保所有页面调弦顺序一致。
- 新增 `AppSettings` 字段时**必须提供默认值**，保持与历史用户 DataStore JSON 向后兼容（已启用 `ignoreUnknownKeys = true`）。

### 7.1 便携工具链（无 Android Studio 依赖）
工具链固定在 `%USERPROFILE%\.android-dev`（不进 OneDrive），缺失时执行 `pwsh .\scripts\setup-toolchain.ps1` 自动重建。所有脚本须用 **PowerShell 7 (`pwsh`)** 执行。

### 7.2 常用命令
```powershell
# Debug APK
pwsh -File scripts/build.ps1

# 签名 Release APK（需根目录临时放置 keystore.properties 与 gtool-release.jks，已加入 .gitignore）
pwsh -File scripts/build.ps1 -Variant release

# 编译单测
pwsh -Command "& '.\scripts\build.ps1' -Tasks @(':app:compileDebugUnitTestKotlin')"
```

> **中文工作区路径单测说明**：当工作区路径包含中文时，Windows 下 Gradle 自带 `TestWorker` 存在 JAR manifest 编码兼容问题（已在 `gradle.properties` 设置 `android.overridePathCheck=true`）。可通过 JDK 21 直接执行 `org.junit.runner.JUnitCore` 运行全部 7 个测试类（52 项单测），Classpath 包含 `debug` 与 `debugUnitTest` 编译目录、JUnit4/Hamcrest/Kotlin-stdlib、Compose transforms `classes.jar` 以及 `android-36/android.jar`。

> **Release 构建说明**：`app/build.gradle.kts` 中 release 构建刻意关闭 `isMinifyEnabled` 与 `isShrinkResources`（开启后曾导致 APK 内 `res/` 异常丢失），优先保证运行稳定性。

### 7.4 发版与 Release 流程
1. 更新 `app/build.gradle.kts` 中的 `versionCode` 与 `versionName`。
2. 同步更新 [docs/工程说明.md](file:///C:/Users/Jon/orca/workspaces/GTool%20App/节拍器界面调整/docs/工程说明.md)、[README.md](file:///C:/Users/Jon/orca/workspaces/GTool%20App/节拍器界面调整/README.md)、[docs/进度.md](file:///C:/Users/Jon/orca/workspaces/GTool%20App/节拍器界面调整/docs/进度.md)。
3. 从主仓库 `C:\Users\Jon\Github\GTool App` 临时拷贝 `keystore.properties` 与 `gtool-release.jks` 至当前工作区，构建 `:app:assembleRelease`，复制产物为 `dist/TickTuner-<version>.apk`，使用 `apksigner verify --print-certs` 验签并计算 SHA-256，随后**立即清理临时拷贝的密钥文件**。
4. 更新 `dist/安装说明.txt`（填入文件名、体积、SHA-256、本次更新说明）。
5. 提交代码、快进合并至 `main`、打 annotated tag `v<version>`、推送 `main` 与 tag，并执行 `gh release create v<version> "dist\TickTuner-<version>.apk" --title "TickTuner v<version>" --notes-file "dist\安装说明.txt"`。
